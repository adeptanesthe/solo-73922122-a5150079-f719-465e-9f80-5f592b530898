# 封口线候选决策树接管试算平台

封口线计划让**候选决策树**先接管一段连续整数温区。本平台用 Flask 提供网页，
支持录入原树、保存候选树与工况草稿、**对候选树做最小误分剪枝**、试算最长
安全温区、确认接管方案，并可输入读数查询实际使用的树与分拣类别。

## 一、数据约定

### 决策树（JSON）

- 叶子节点：`{"leaf": "类别名"}`，类别为非空字符串。
- 分支节点：

  ```json
  {"feature": "temperature", "threshold": 200, "left": {...}, "right": {...}}
  ```

  - `feature` 仅允许 `temperature`（温度）、`front`（前压）、`back`（后压）；
  - `threshold` 为 0..65535 的整数；读数 **≤ 阈值走 `left`，> 阈值走 `right`**；
  - 每棵树至多 **128 个叶子**，超出拒绝保存。

### 工况草稿（四个整数闭区间）

| 字段 | 含义 | 范围 |
| --- | --- | --- |
| `temperature` | 温度区间 | 0..65535 |
| `front` | 前压区间 | 0..65535 |
| `back` | 后压区间 | 0..65535 |
| `diff` | 后压−前压区间 | -65535..65535 |

区间均为 `[下限, 上限]`，下限不得大于上限；布尔值不被当作整数接受。

## 二、试算规则（不枚举读数组合）

在当前草稿上求**最长连续整数温区**，要求：

1. 温区内**每个温度**都存在合规压力组合（前压、后压在各自区间内，且
   后压−前压落在压差区间内）；
2. 对所有合规读数，原树与候选树判为**同一分拣类别**；
3. 多个等长温区时取**起点最低**者。

算法（见 `app/solver.py`、`app/tree.py`）：

1. 把两棵树展开为至多 128 个**轴对齐叶子盒子**（区间表示，非逐点枚举），
   分支按阈值切区间，空区间整枝剪枝；
2. 压差可行性用**闭式区间判据**：独立闭区间上 `back-front` 的取值范围为
   `[back_lo-front_hi, back_hi-front_lo]`，与压差区间判断相交即可，
   不需要枚举任何 `(front, back)` 组合；
3. 对两树**类别不同**的叶子盒子对，先与工况域求交裁剪，再判裁剪后的
   压力矩形是否满足压差约束，收集分歧温度区间并做区间合并；
4. 在工况温度区间上求补、合并，扫描最长连续整数段（平局取起点最低）。

复杂度上界为叶子对级别的区间运算 `O(128×128)` 加温度轴线性合并，
压力组合从不枚举；实测两棵 128 叶满树、满量程工况为毫秒级。

## 三、候选树剪枝（动态规划，不穷举剪枝组合）

在网页第 ④ 区录入**叶数上限（1～128 的整数）**与 **1～500 条样品**，每条含：

| 字段 | 含义 | 约束 |
| --- | --- | --- |
| `temperature` | 温度 | 0..65535 整数 |
| `front` | 前压 | 0..65535 整数 |
| `back` | 后压 | 0..65535 整数 |
| `category` | 复验类别 | 非空字符串 |
| `locked` | 是否锁定现判 | 布尔 `true`/`false` |

### 剪枝规则

- 每个分支节点只有两种处置：**保留原分支**，或把**整棵子树收成一个叶子**；
- 收成叶子时，叶子类别**只能从该子树原有的叶子类别中选择**，不得引入新类别；
- **锁定样品（`locked=true`）剪枝前后的预测必须完全相同**（硬约束）；
- 在叶数不超过上限的所有可行剪枝中，选**误分样品数最少**的；误分相同时
  取**叶子更少**的；
- 不允许枚举“每个内部节点剪/不剪”的全部组合（最多 127 个内部节点，组合数
  指数级）。

### 算法（见 `app/pruning.py`）

在树节点上做自底向上的动态规划，状态为

`dp[u][k][c] = 子树 u 剪成恰好 k 个叶子、根处置为 c 时的最小误分样品数（含回溯指针）`

- 叶子节点只能原样保留（单叶子树“收成叶子”的可选类别只有它自己）；
- 内部节点：
  - **收成叶子**：`k=1`，类别取自该子树原有叶子类别，且必须让所有经过该
    节点的锁定样品预测保持不变，否则该类别不可行；
  - **保留分支**：`k=k1+k2`，左右子树各取最优解，做一次叶数卷积，误分相加；
- 同一 `(叶数, 根处置)` 只保留误分最小的状态，最终在根节点按
  “误分最少、再叶数最少”裁决并回溯重建剪枝后的树。

树节点与叶数均不超过 128、样品不超过 500，复杂度约
`O(节点数 × max_leaves² × 子树样品数)`，128 叶满树 + 500 条样品实测毫秒级；
剪枝组合从不枚举。产出后还会独立复核叶数上限、锁定零违约与误分数。

### 剪枝与草稿版号

- 剪枝在**后台守护线程**执行，剪枝期间仍可随时保存草稿，互不阻塞；
- 每个剪枝任务绑定发起时的 `revision` 与候选树快照；
- **只有启动时的版号仍有效**，成功结果才会自动替换草稿里的候选树
  （替换本身使 `revision` 自增）；
- 期间草稿被保存过（哪怕改回原值）、剪枝**无解**或**计算失败**时，
  **保留最新草稿**，任务记录里写明中文原因；
- 候选树换版后，旧的温区试算立即标记为“已过期”、不能再确认；
  线上继续按**已确认的接管方案**分流（确认时已固化候选树快照，不受换版影响）。

## 四、试算与确认的状态机

- 试算在**后台守护线程**执行，试算期间可以继续保存草稿，互不阻塞。
- 每次保存原树/草稿/确认都会使 `revision` 自增；每个试算任务绑定发起时的
  `revision` 与当时的树/草稿快照。
- 草稿一旦被修改（**即使改回原值**），旧试算立即标记为“已过期”，
  确认接口返回 409 并说明原因，必须用当前草稿重新试算。
- 只接受**当前草稿的成功试算**；试算无解、失败、进行中、过期均拒绝确认，
  响应中给出中文原因，并沿用当前分流（原树）。
- 确认后固化的是**确认时刻的候选树快照、工况与温区**；后续再改草稿不影响
  已确认方案。

## 五、确认后的分流规则

读数 `(temperature, front, back)` 仅在**同时**满足以下条件时使用候选树：

1. 温度落在已确认温区 `[zone_lo, zone_hi]` 内；
2. 前压、后压落在获准工况区间内；
3. `back - front` 落在获准压差区间内。

其余所有读数（温区外、任一压力不合规、压差不合规、无确认方案）一律使用原树。
查询接口会返回所用树、类别与逐条判定依据。

## 六、运行方式（Docker Compose）

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000
```

- 状态文件持久化在宿主机 `./data/state.json`（容器内 `/app/data`）。
- 停止：`docker compose down`（数据保留）。

本地无 Docker 时的等价运行方式：

```bash
pip install -r requirements.txt
SEAL_DATA_FILE=data/state.json python -m flask --app "app.web:create_app" run --port 8000
```

## 七、HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 操作页面 |
| GET | `/api/state` | 树、草稿、确认方案、revision、温区试算与剪枝任务列表 |
| GET | `/api/examples` | 三组温区试算内置示例 |
| GET | `/api/pruning-examples` | 两组剪枝内置示例 |
| POST | `/api/original-tree` | 保存原树 `{"tree": ...}` |
| POST | `/api/draft` | 保存候选树与工况 `{"candidate_tree": ..., "draft": ...}` |
| POST | `/api/trials` | 发起后台温区试算，返回 `job_id` |
| GET | `/api/trials/<id>` | 查询温区试算状态/结果/是否过期 |
| POST | `/api/pruning` | 发起后台剪枝 `{"max_leaves":1..128, "samples":[...]}` |
| GET | `/api/pruning/<id>` | 查询剪枝状态、剪枝前后叶数/误分、是否替换草稿及原因 |
| POST | `/api/confirmations` | 确认 `{"trial_id": ...}`，失败返回 409 与原因 |
| POST | `/api/classify` | 读数查询 `{"temperature","front","back"}` |

剪枝任务对象中的关键字段：`status`（`solved`/`no_solution`/`error` 等）、
`stale`（版号是否已变化）、`applied`（结果是否已替换草稿候选树）、
`apply_reason`（替换或保留草稿的中文原因），以及 `result.leaves_before/
leaves_after`、`result.misclass_before/misclass_after`、
`result.locked_total/locked_violations`。

## 八、内置示例（页面一键载入）

温区试算：

1. **可成功试算**：两树仅在高温高后压处分歧（原树 REJECT / 候选 REWORK），
   最长安全温区 `[150,200]`（51 个温度）。
2. **压差无解**：后压最大 120、前压最小 100，无法满足压差 `[100,200]`，
   无任何合规压力组合。
3. **无安全温区**：压力可行但两树在工况温区每个温度上都存在分歧读数。

候选树剪枝：

4. **剪枝示例 A（成功）**：8 叶三层树、16 条样品（含 2 条锁定），叶数上限 4，
   最优剪枝为 8 叶 → 2 叶、误分 7 → 0，锁定样品预测不变，结果自动替换草稿。
5. **剪枝示例 B（无解）**：叶数上限 1，但两条锁定样品在根处预测不同
   （PASS / REJECT），根无法收成单一类别而保留分支至少需 2 叶 → 无解，
   草稿保留不变。

## 九、自测

```bash
python -m unittest discover -s tests -v
```

- `tests/test_solver.py`：500 组随机小树与**全量枚举暴力法**逐例对照
  （暴力枚举仅存在于测试中）、128 叶满树 × 65535 满量程性能与边界、
  平局起点规则、压差裁剪、叶子盒子完备互斥抽查。
- `tests/test_pruning.py`：300 组随机小树与**全量枚举所有剪枝组合的暴力法**
  逐例对照（暴力枚举仅存在于测试中）、锁定预测不变、锁定冲突无解、

  压差/压力越界的用树选择、**旧试算过期与“改回原值仍被拒”**、
  试算中保存草稿、无解/失败拒绝确认、输入校验、重启持久化。
- `tests/test_pruning_web.py`：剪枝成功自动替换候选树、**剪枝期间改稿导致
  版号变化时保留最新草稿**、剪枝中保存草稿不被阻塞、无解保留草稿、
  入参校验、未保存候选树拒绝、重启后替换结果持久化。

## 十、目录结构

```
app/
  tree.py        # 树校验、叶子盒子、分类路由
  solver.py      # 温区试算：不枚举的区间求解器
  pruning.py     # 候选树剪枝：不穷举组合的动态规划求解器
  validation.py  # 工况与读数校验
  store.py       # 线程安全 JSON 持久化 + 内存试算/剪枝任务
  examples.py    # 内置示例（温区试算 + 剪枝）
  web.py         # Flask 路由
templates/ static/   # 网页
tests/               # 自测
Dockerfile docker-compose.yml requirements.txt
```
